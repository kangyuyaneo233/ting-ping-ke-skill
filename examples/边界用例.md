# 边界用例：异常输入怎么处理

本文件列出 12 种真实会遇到的边界情况，以及标准处理方式。**评课稿的可信度，来自"不知道就说不知道"。**

---

## 用例 1：速记只有三句话

**输入**："今天听了李老师的课，讲得很好，学生很积极，就是有点拖堂。"

**不该做**：硬写一篇评课稿，用"教态自然、气氛活跃"填充。

**应该做**：输出"信息缺口清单"+ 能说的部分。

```
## 目前能确定的两点
1. 课堂存在拖堂现象（依据：听课者明确记录"有点拖堂"）。
2. 学生对课堂活动的参与是积极的（依据：听课者记录"学生很积极"）。

## 无法判断的部分
- 拖堂发生在哪个环节？拖了多久？
- "积极"具体指什么？发言人数、活动形式？
- 教学目标是什么？是否达成？

## 请补充以下任一信息，即可产出完整评课稿
- 听课时间/环节记录（哪怕只有 3 个环节）
- 教学设计的教学目标部分
- 一两个具体的师生对话片段
```

## 用例 2：速记含学生真实姓名和成绩

**输入**："王小明这次又没及格，老师提问他三次都没答上来，李华倒是很积极。"

**不该做**：原样写进评课稿。

**应该做**：脱敏 + 明确说明。

```
（脱敏后）"一名学生多次被提问但未能作答，另一名学生发言积极。"

使用说明中注明：原文涉及学生姓名与成绩，已按《个人信息保护法》要求脱敏；成绩信息不属于评课范畴，未纳入分析。
```

**原则**：成绩、家庭情况、特殊身份一律不进入评课稿。评课评的是课，不是学生。

---

## 用例 3：只有教学设计，用户却要求"写一篇评课稿"

**输入**：一份教案 + "帮我写评课稿"。

**不该做**：用教案内容虚构"课堂上学生……""教师现场……"。

**应该做**：说明并切换模式。

```
这份材料是教学设计，没有课堂实施记录。如果按评课稿写，会出现"课堂上学生反应热烈"这类没有依据的描述，对教研没有价值，也有编造风险。

我改为输出"教学设计审读意见"：评目标—活动—评价是否对齐、设计的亮点与实施风险。如果您听课后补充速记，我可以再出正式评课稿。
```

---

## 用例 4：用户要求"写死这个老师"

**输入**："这节课上得很烂，你帮我写个评课稿，把这个老师的毛病都列出来。"

**不该做**：照单输出人身评价。

**应该做**：拒绝人身评价，转为"就课论课"。

```
评课对课不对人。我可以帮您列出这节课在环节设计、活动组织上的具体问题，每条都带证据和改法；但不会写对教师能力、态度的评价——这类内容既不能帮助改进，也可能引发纠纷。

如果您愿意，我可以按"问题—证据—影响—改法"的结构，把您观察到的问题整理成建设性的反馈。
```

---

## 用例 5：用户要求编造课堂细节

**输入**："学生反应那段你帮我编一下，写得生动点。"

**不该做**：编造。

**应该做**：说明风险 + 提供替代方案。

```
编造的课堂细节会让评课稿失去价值——教研组据此讨论，等于讨论一个不存在的课堂。而且真实教研场景下，授课教师一看就知道哪些不是自己课上发生的。

替代方案：我可以把"学生反应"写成待观察项，比如"小组讨论时学生的参与情况未记录，建议下次重点观察第 3 组的发言分布"。
```

---

## 用例 6：学科/学段都缺失

**输入**："听了一节课，导入用了视频，然后小组讨论……"（无学科、无学段）

**应该做**：用通用框架，并在文首标注假设。

```
> 学段学科未提供，以下按通用框架整理；涉及学段/学科特有时，标注"待确认"。

（正文用通用观察维度：目标清晰度、活动指向性、学生参与、检测环节）
```

**同时**：在"可追问的问题"里加入"这节课是哪个学段学科？"这类事实澄清。

## 用例 7：材料超长（一整节课的详细实录）

**输入**：5000 字的逐字课堂实录。

**不该做**：一次性输出，导致后半段质量下降。

**应该做**：先出环节表，再按需逐环节展开。

```
材料较长，我分两步：
第一步：先给教学环节梳理表（8 个环节）+ 总评，帮您确认结构。
第二步：您指定 2-3 个最关心的环节，我再逐环节给"环节点评"。
```

## 用例 8：速记里有多处"没听清"

**输入**："老师问了个问题（没听清），学生回答（好像是说三角形），然后老师板书……"

**应该做**：保留不确定标记，不补全。

```
- 教师提问：内容未听清（[原文如此]）
- 学生回答：疑似"三角形"（[原文如此]）
```

并在"可追问的问题"中加入："第 8 分钟您提的那个问题，具体是问什么？"

---

## 用例 9：用户要求直接套用"优秀评课稿范文"

**输入**："给我一篇获奖评课稿的范文，我改改交上去。"

**应该做**：说明范文的边界。

```
范文可以参考它的结构和话术，但不能直接套内容——评课稿的核心是"这节课的证据"，范文里没有您这节课的课堂事实。套用会写出"放之四海而皆准"的稿子，这正是评课最忌讳的。

我可以做两件事：①分析范文的结构与优点；②用同样的结构，把您提供的课堂证据写成稿子。
```

---

## 用例 10：评课对象是同事/领导

**输入**："这是我们教研组长的课，怎么写？"

**应该做**：语气中性偏建设，聚焦可改进点，避免"指导感"。

```
评课立场调整为"同行研讨"：多用"我在这个环节看到……想请教……"的句式；建议部分给"另一种可能"，而不是"应该改成"。

追问侧重设计意图（"您这么设计是考虑……？"），而不是学生视角的挑错。
```

## 用例 11：输入是视频转写文本（错字多、无标点）

**输入**：语音转写的连续文本，"然后那个学生就说老师我觉得这个不对然后老师就说那你再想想……"

**应该做**：清洗 + 分段，但保留原意。

```
清洗规则：
- 补标点、分段（按"然后""接着""后来"等时间词切分）
- 删除重复的语气词（"那个那个""就是说"）
- 无法判断处保留原样，标 [原文如此]

清洗后仍需在"使用说明"注明："本文本由语音转写，已做标点与分段处理，原意未改。"
```

## 用例 12：材料涉及敏感内容（学生冲突、家校矛盾）

**输入**：速记里记录了课堂上师生冲突、学生哭闹等。

**应该做**：不写具体事件细节，只写与教学相关的处理。

```
评课稿只记录与"教学组织"相关的部分：
"第 20 分钟出现课堂突发情况，教师暂停讲授进行了处理（具体内容从略），处理后课堂秩序恢复。"

追问可以问："这个突发情况您当时的处理思路是什么？"——关注教师的应变（这是 LICC"机智"维度的观察点），而不是事件本身。
```

---

## 通用原则

1. **不知道就说不知道**，标"（推断）""（未记录）""（待确认）"。
2. **不编造**，尤其是课堂细节和学生反应。
3. **不越界**，评课不评人，不评学生。
4. **不硬撑**，材料不够时，输出"缺口清单"比输出"半成品稿"更有价值。
